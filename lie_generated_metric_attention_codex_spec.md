# Lie-Generated Metric Attention (LGMA)

A Codex-ready implementation specification for generating multi-head attention transformations from a small Lie-algebra basis.

## One-sentence idea

Multi-head attention learns many independent bilinear views of the same token vectors; LGMA instead learns one or two base query/key/value representations and generates many effective heads using structured metrics

$$
M_h = \exp\left(\sum_{r=1}^{m} \theta_{hr} A_r\right).
$$

Here, each head is not an unrelated learned projection. Each head is a point on a low-dimensional transformation family generated by learned matrices $A_r$ and head-specific coordinates $\theta_{hr}$.

---

# 1. Goal

Implement a PyTorch attention layer that can be dropped into a small Transformer block and compared against standard multi-head attention.

The first prototype should answer:

1. Can one shared query projection and one shared key projection produce several useful attention heads when the head-specific differences come from generated metrics $M_h$?
2. Does the generated-head formulation reduce redundant Q/K/V parameters and KV-cache size?
3. Do the generated heads produce diverse attention maps?
4. Can diagonal, block-diagonal, or low-rank generator parameterizations make the method computationally attractive?

---

# 2. Standard multi-head attention as bilinear geometry

Let a token vector be

$$
x_i \in \mathbb{R}^{d_{model}}.
$$

A standard attention head computes

$$
q_i^{(h)} = W_Q^{(h)}x_i,
\qquad
k_j^{(h)} = W_K^{(h)}x_j.
$$

The attention score is

$$
\mathrm{score}_{ij}^{(h)}
= (q_i^{(h)})^T k_j^{(h)}.
$$

Substitute the projections:

$$
\mathrm{score}_{ij}^{(h)}
= (W_Q^{(h)}x_i)^T(W_K^{(h)}x_j)
= x_i^T\left(W_Q^{(h)T}W_K^{(h)}\right)x_j.
$$

Define

$$
B_h = W_Q^{(h)T}W_K^{(h)}.
$$

Then

$$
\mathrm{score}_{ij}^{(h)} = x_i^T B_h x_j.
$$

So each attention head defines a learned bilinear comparison geometry $B_h$.

Standard multi-head attention learns many such geometries:

$$
B_1, B_2, \dots, B_H.
$$

LGMA replaces many independent $B_h$ geometries with generated metrics in a shared latent space.

---

# 3. Proposed model

Use shared base projections:

$$
q_i = W_Qx_i,
\qquad
k_i = W_Kx_i,
\qquad
v_i = W_Vx_i.
$$

For head $h$, define a generated metric:

$$
M_h = \exp\left(\sum_{r=1}^{m}\theta_{hr}A_r\right).
$$

Then score token $i$ against token $j$ using

$$
\mathrm{score}_{ij}^{(h)} = q_i^T M_h k_j.
$$

This creates different attention maps across heads even though all heads share the same base $q_i$ and $k_j$ vectors.

The induced original-space bilinear form is

$$
B_h = W_Q^T M_h W_K.
$$

Important relationship:

$$
\boxed{B_h = W_Q^T M_h W_K.}
$$

Interpretation:

- $M_h$ lives in the shared query/key latent space.
- $B_h$ is the effective head-specific comparison matrix in the original token space.
- Standard MHA learns $B_h$ indirectly through independent $W_Q^{(h)}$ and $W_K^{(h)}$.
- LGMA learns $W_Q,W_K$ once and generates many $M_h$ from a small learned algebra.

---

# 4. Relationship to query/key transformations

Another way to write the idea is to transform the shared query/key vectors:

$$
q_i^{(h)} = T_h^Q q_i,
\qquad
k_j^{(h)} = T_h^K k_j.
$$

Then

$$
(q_i^{(h)})^T k_j^{(h)}
= (T_h^Q q_i)^T(T_h^K k_j)
= q_i^T (T_h^Q)^T T_h^K k_j.
$$

So

$$
M_h = (T_h^Q)^T T_h^K.
$$

With an optional base metric $M_0$:

$$
M_h = (T_h^Q)^T M_0 T_h^K.
$$

For the first implementation, use the direct metric form:

$$
\mathrm{score}_{ij}^{(h)} = q_i^T M_h k_j.
$$

This avoids unnecessary ambiguity and makes the code simpler.

---

# 5. Critical algebraic warning

Do not apply the same orthogonal transform to both query and key and expect distinct heads.

If

$$
q^{(h)} = R_h q,
\qquad
k^{(h)} = R_h k,
$$

and

$$
R_h^TR_h = I,
$$

then

$$
(R_hq)^T(R_hk) = q^TR_h^TR_hk = q^Tk.
$$

The score is unchanged. All such heads collapse to the same attention map.

Therefore, the transformation must change the query-key metric. The direct metric formulation does this by construction:

$$
q_i^T M_h k_j.
$$

---

# 6. Forward pass equations

For input

$$
X \in \mathbb{R}^{B \times T \times d_{model}},
$$

compute shared base projections:

$$
Q = XW_Q,
\qquad
K = XW_K,
\qquad
V = XW_V.
$$

For the MVP, choose

$$
Q,K,V \in \mathbb{R}^{B \times T \times d_{head}}.
$$

For each head:

$$
G_h = \sum_{r=1}^{m}\theta_{hr}A_r,
$$

$$
M_h = \exp(G_h),
$$

$$
S_h = \frac{QM_hK^T}{\sqrt{d_{head}}},
$$

$$
P_h = \mathrm{softmax}(S_h + \mathrm{mask}),
$$

$$
O_h = P_hV.
$$

Concatenate and project:

$$
O = \mathrm{Concat}(O_1,\dots,O_H)W_O.
$$

Final output:

$$
O \in \mathbb{R}^{B \times T \times d_{model}}.
$$

# 8. MVP parameter shapes

For the first implementation:

```python
self.q_proj = nn.Linear(d_model, head_dim, bias=bias)
self.k_proj = nn.Linear(d_model, head_dim, bias=bias)
self.v_proj = nn.Linear(d_model, head_dim, bias=bias)
self.out_proj = nn.Linear(num_heads * head_dim, d_model, bias=bias)
```

Generator parameters:

```python
self.generators = nn.Parameter(torch.empty(num_generators, head_dim, head_dim))
self.theta = nn.Parameter(torch.empty(num_heads, num_generators))
```

Compute the head generators:

```python
G = torch.einsum("hm,mde->hde", self.theta, self.generators)
M = torch.matrix_exp(G)
```

Shapes:

```python
G.shape == (num_heads, head_dim, head_dim)
M.shape == (num_heads, head_dim, head_dim)
```

Attention scores:

```python
scores = torch.einsum("btd,hde,bse->bhts", q, M, k)
scores = scores / math.sqrt(head_dim)
```

Shapes:

```python
q.shape == (batch, seq_len, head_dim)
k.shape == (batch, seq_len, head_dim)
v.shape == (batch, seq_len, head_dim)
scores.shape == (batch, num_heads, seq_len, seq_len)
```

Attention output:

```python
attn = torch.softmax(scores, dim=-1)
attn = self.attn_dropout(attn)
out_heads = torch.einsum("bhts,bsd->bhtd", attn, v)
out_heads = out_heads.transpose(1, 2).contiguous()
out_heads = out_heads.view(batch, seq_len, num_heads * head_dim)
out = self.out_proj(out_heads)
```

# 9. SDPA-compatible implementation

The score

$$
q_i^T M_h k_j
$$

can be computed by transforming queries:

$$
\tilde{q}_i^{(h)} = q_i^T M_h.
$$

In PyTorch row-vector notation:

```python
q_tilde = torch.einsum("btd,hde->bhte", q, M)
```

Then expand keys and values as views:

```python
k_expanded = k[:, None, :, :].expand(batch, num_heads, seq_len, head_dim)
v_expanded = v[:, None, :, :].expand(batch, num_heads, seq_len, head_dim)
```

Then use PyTorch scaled dot-product attention:

```python
out_heads = F.scaled_dot_product_attention(
    q_tilde,
    k_expanded,
    v_expanded,
    attn_mask=prepared_attn_mask,
    dropout_p=self.dropout if self.training else 0.0,
    is_causal=self.causal,
)
```

Expected shape:

```python
out_heads.shape == (batch, num_heads, seq_len, head_dim)
```

Then reshape:

```python
out_heads = out_heads.transpose(1, 2).contiguous()
out_heads = out_heads.view(batch, seq_len, num_heads * head_dim)
out = self.out_proj(out_heads)
```

This path is preferable when `need_weights=False`, because it can use optimized attention kernels.

When `need_weights=True`, use the explicit softmax path so attention matrices can be returned.

# 10. Generator types

Implement these in this order.

## 10.1 Full generator

Each generator is a dense matrix:

$$
A_r \in \mathbb{R}^{d_{head} \times d_{head}}.
$$

Code:

```python
G = torch.einsum("hm,mde->hde", theta, generators)
M = torch.matrix_exp(G)
```

Pros:

- Closest to the mathematical proposal.
- Most expressive.
- Useful for correctness and proof-of-concept experiments.

Cons:

- Full matrix exponentials can be expensive.
- Full $A_r$ can become numerically unstable if not regularized.

## 10.2 Diagonal generator

Represent each generator by a vector:

$$
a_r \in \mathbb{R}^{d_{head}}.
$$

Then

$$
G_h = \mathrm{diag}\left(\sum_{r=1}^{m}\theta_{hr}a_r\right),
$$

and

$$
M_h = \mathrm{diag}\left(\exp\left(\sum_{r=1}^{m}\theta_{hr}a_r\right)\right).
$$

Code:

```python
g = torch.einsum("hm,md->hd", theta, diag_generators)
scale = torch.exp(g)
q_tilde = q[:, None, :, :] * scale[None, :, None, :]
```

Then use either explicit scores:

```python
scores = torch.einsum("bhtd,bsd->bhts", q_tilde, k)
```

or SDPA:

```python
out_heads = F.scaled_dot_product_attention(q_tilde, k_expanded, v_expanded, ...)
```

Pros:

- Very fast.
- Very simple.
- No `torch.matrix_exp` over dense matrices.
- Good first efficiency baseline.

Cons:

- Only coordinate-wise reweighting.
- No cross-coordinate interactions.

## 10.3 Symmetric generator

If each $A_r$ is symmetric, then

$$
M_h = \exp(G_h)
$$

is symmetric positive definite when $G_h$ is symmetric.

This makes $M_h$ a true metric-like matrix.

Implementation:

```python
raw = self.raw_generators
A = 0.5 * (raw + raw.transpose(-1, -2))
```

Pros:

- Stronger metric interpretation.
- Positive eigenvalues after exponentiation.

Cons:

- Less general than arbitrary bilinear comparators.

## 10.4 Skew-symmetric generator

If each $A_r$ is skew-symmetric, then

$$
\exp(A_r)
$$

is orthogonal. This creates rotation-like transformations.

Implementation:

```python
raw = self.raw_generators
A = 0.5 * (raw - raw.transpose(-1, -2))
```

Warning:

If the same orthogonal transform is applied symmetrically to Q and K, the dot product may be unchanged. In the direct metric version $q^T M_h k$, skew generators still create nontrivial $M_h$, but pure orthogonal metrics may not be sufficient. Test carefully.

## 10.5 Block-diagonal generator

Partition the dimension into blocks of size `block_size` and use independent small matrices per block.

Pros:

- More expressive than diagonal.
- Cheaper than full.
- Useful compromise.

Implementation can initially be simple and less optimized:

1. Store block generators as `(num_generators, num_blocks, block_size, block_size)`.
2. Generate block matrices with `torch.matrix_exp` per block.
3. Apply blockwise to `q`.

Optimize later if this variant performs well.

# 11. Initialization

A bad initialization can make all generated heads identical or numerically unstable.

Recommended MVP initialization:

```python
nn.init.xavier_uniform_(self.q_proj.weight)
nn.init.xavier_uniform_(self.k_proj.weight)
nn.init.xavier_uniform_(self.v_proj.weight)
nn.init.xavier_uniform_(self.out_proj.weight)
```

For full generators:

```python
std = 0.02 / math.sqrt(head_dim)
self.generators.data.normal_(mean=0.0, std=std)
```

For head coordinates:

```python
self.theta.data.normal_(mean=0.0, std=0.02)
```

Important: do not initialize both `generators` and `theta` to exactly zero, because then all heads start with

$$
M_h = I
$$

and all attention maps are identical.

A stable alternative:

```python
self.theta.data.normal_(0.0, 0.02)
self.generators.data.normal_(0.0, 0.02 / math.sqrt(head_dim))
```

Then metrics start close to identity but not exactly identical.

# 12. Stabilization and regularization

Full matrix exponentials can produce large norms. Add stabilization options.

## 12.1 Trace-zero generators

Subtract the trace component:

$$
A_r \leftarrow A_r - \frac{\mathrm{tr}(A_r)}{d}I.
$$

This prevents exponential volume scaling from dominating early training.

Code:

```python
def make_trace_zero(A: torch.Tensor) -> torch.Tensor:
    d = A.shape[-1]
    tr = A.diagonal(dim1=-2, dim2=-1).sum(-1)
    eye = torch.eye(d, device=A.device, dtype=A.dtype)
    return A - (tr[..., None, None] / d) * eye
```

## 12.2 Generator norm penalty

Optional loss term:

$$
\lambda_A \sum_r ||A_r||_F^2.
$$

## 12.3 Head diversity penalty

Encourage generated metrics to differ:

$$
\mathcal{L}_{div}
= \frac{1}{H(H-1)}\sum_{h \neq h'}
\frac{\langle \mathrm{vec}(M_h),\mathrm{vec}(M_{h'})\rangle}
{||M_h||_F ||M_{h'}||_F}.
$$

Minimize this term or log it as a diagnostic first.

Do not add too many regularizers initially. First get the layer working and compare behavior.

# 13. Mask handling

Support:

1. Causal mask.
2. Additive attention mask.
3. Boolean attention mask.
4. Key padding mask.

For explicit score path:

```python
scores.shape == (batch, num_heads, seq_len, seq_len)
```

Add masks before softmax.

Boolean masks should be converted so that masked positions get a large negative value:

```python
scores = scores.masked_fill(mask, torch.finfo(scores.dtype).min)
```

Use care with float16/bfloat16. If needed, use `-1e4` for half precision instead of `finfo.min`.

Causal mask:

```python
causal_mask = torch.ones(seq_len, seq_len, device=x.device, dtype=torch.bool).triu(1)
scores = scores.masked_fill(causal_mask[None, None, :, :], neg_large)
```

Key padding mask shape:

```python
key_padding_mask.shape == (batch, seq_len)
```

If True means padded, apply:

```python
scores = scores.masked_fill(key_padding_mask[:, None, None, :], neg_large)
```

# 14. Value-side variants

The MVP uses shared values:

$$
O_h = P_hV.
$$

This is simple and tests whether different generated metrics alone can produce useful head diversity.

Later variants:

## 14.1 Generated value transform

Generate value transforms:

$$
R_h = \exp\left(\sum_{r=1}^{m_v}\phi_{hr}C_r\right),
$$

and use

$$
O_h = P_h(VR_h).
$$

In PyTorch row notation:

```python
v_h = torch.einsum("btd,hde->bhte", v, R)
out_heads = torch.einsum("bhts,bhsd->bhtd", attn, v_h)
```

## 14.2 Diagonal value transform

Cheaper:

$$
R_h = \mathrm{diag}(r_h).
$$

```python
v_h = v[:, None, :, :] * r[None, :, None, :]
```

## 14.3 Warning about value-only transformations

If all heads share the same attention weights and only values are transformed, then

$$
\sum_j \alpha_{ij}T_hv_j = T_h\sum_j\alpha_{ij}v_j.
$$

This can often be absorbed into a later linear layer. For true multi-head behavior, transformations should affect query-key scores through $M_h$.

# 15. Parameter count comparison

Assume standard MHA uses total model dimension $d_{model}$ and $H$ heads with

$$
d_{head} = d_{model}/H.
$$

Standard Q/K/V projections have parameter count approximately:

$$
3d_{model}^2.
$$

LGMA MVP has:

$$
3d_{model}d_{head}
$$

for Q/K/V, plus generators:

$$
md_{head}^2 + Hm
$$

for full generators and head coordinates.

The output projection is still

$$
d_{model}^2
$$

if concatenating $H$ outputs of dimension $d_{head}$.

Therefore, the MVP can substantially reduce Q/K/V projection parameters, especially when $H$ is large.

KV-cache implication for autoregressive inference:

- Standard MHA caches K and V for all heads: roughly $2T d_{model}$ values per layer.
- LGMA MVP caches shared K and V: roughly $2T d_{head}$ values per layer, plus fixed metric parameters.

This is one of the most important practical motivations.

---

# 16. Efficiency caveats

LGMA does not automatically remove the quadratic attention cost.

If it computes $H$ attention maps over a length-$T$ sequence, then score computation is still roughly

$$
O(HT^2d_{head}).
$$

If $Hd_{head}=d_{model}$, this is similar to standard attention score cost.

The likely efficiency gains are initially from:

1. fewer Q/K/V projection parameters,
2. smaller KV cache,
3. shared K/V storage,
4. cheaper head generation if $M_h$ is diagonal or block-diagonal,
5. possibly fewer effective heads if the generated-head family works with smaller $H$.

Do not claim that the full-generator MVP is faster than FlashAttention or optimized MHA. Treat speed as an empirical question.

# 17. Diagnostics to log

For each layer, log:

## 17.1 Metric norm

$$
||M_h||_F.
$$

## 17.2 Generator norm

$$
||A_r||_F.
$$

## 17.3 Metric diversity

Cosine similarity between flattened metrics:

$$
\mathrm{cos}(M_h,M_{h'}).
$$

## 17.4 Attention diversity

Cosine similarity or average KL divergence between attention matrices:

$$
P_h, P_{h'}.
$$

## 17.5 Head entropy

For each head:

$$
-\sum_j P_{ij}^{(h)}\log P_{ij}^{(h)}.
$$

This helps detect heads that become uniform or overly sharp.

## 17.6 Conditioning

For full metrics:

```python
singular_values = torch.linalg.svdvals(M)
condition_number = singular_values[..., 0] / singular_values[..., -1].clamp_min(1e-8)
```

Log but do not necessarily optimize at first.

## 18.4 Metric relation test

Verify that

$$
q_i^TM_hk_j = x_i^TW_Q^TM_hW_Kx_j.
$$

This catches transposition mistakes.

Pseudo-test:

```python
def test_metric_relation():
    torch.manual_seed(0)
    d_model = 5
    d_head = 3
    Wq = torch.randn(d_head, d_model)
    Wk = torch.randn(d_head, d_model)
    M = torch.randn(d_head, d_head)
    xi = torch.randn(d_model)
    xj = torch.randn(d_model)

    q = Wq @ xi
    k = Wk @ xj
    left = q @ M @ k

    B = Wq.T @ M @ Wk
    right = xi @ B @ xj

    assert torch.allclose(left, right, atol=1e-5)
```

Adjust this test if using PyTorch `nn.Linear`, where weights are stored as `(out_features, in_features)`.

## 18.5 Identity-collapse test

When all $M_h=I$, all attention maps should be identical.

Set:

```python
layer.theta.data.zero_()
```

Since

$$
M_h = \exp(0)=I,
$$

all heads should produce the same attention weights before dropout.

This is not desirable for training, but it is a useful correctness test.

## 18.6 Causal mask test

Verify that future positions receive zero probability.

```python
_, attn = layer(x, need_weights=True)
assert torch.allclose(attn[..., torch.triu(torch.ones(T, T), diagonal=1).bool()], torch.zeros_like(...))
```

Implement carefully because boolean indexing can flatten dimensions.

```python
import math
from typing import Optional

import torch
from torch import nn
import torch.nn.functional as F


class LieGeneratedMetricAttention(nn.Module):
    def __init__(
        self,
        d_model: int,
        num_heads: int,
        head_dim: int,
        num_generators: int,
        dropout: float = 0.0,
        bias: bool = False,
        generator_type: str = "full",
        use_sdpa: bool = True,
        causal: bool = False,
        stabilize_generators: bool = True,
        return_metrics: bool = False,
    ) -> None:
        super().__init__()
        if generator_type not in {"full", "diagonal", "symmetric", "skew"}:
            raise ValueError(f"Unsupported generator_type: {generator_type}")

        self.d_model = d_model
        self.num_heads = num_heads
        self.head_dim = head_dim
        self.num_generators = num_generators
        self.generator_type = generator_type
        self.use_sdpa = use_sdpa
        self.causal = causal
        self.stabilize_generators = stabilize_generators
        self.return_metrics = return_metrics
        self.dropout = dropout

        self.q_proj = nn.Linear(d_model, head_dim, bias=bias)
        self.k_proj = nn.Linear(d_model, head_dim, bias=bias)
        self.v_proj = nn.Linear(d_model, head_dim, bias=bias)
        self.out_proj = nn.Linear(num_heads * head_dim, d_model, bias=bias)

        if generator_type == "diagonal":
            self.generators = nn.Parameter(torch.empty(num_generators, head_dim))
        else:
            self.generators = nn.Parameter(torch.empty(num_generators, head_dim, head_dim))

        self.theta = nn.Parameter(torch.empty(num_heads, num_generators))
        self.attn_dropout = nn.Dropout(dropout)
        self.resid_dropout = nn.Dropout(dropout)

        self.reset_parameters()

    def reset_parameters(self) -> None:
        nn.init.xavier_uniform_(self.q_proj.weight)
        nn.init.xavier_uniform_(self.k_proj.weight)
        nn.init.xavier_uniform_(self.v_proj.weight)
        nn.init.xavier_uniform_(self.out_proj.weight)

        if self.q_proj.bias is not None:
            nn.init.zeros_(self.q_proj.bias)
            nn.init.zeros_(self.k_proj.bias)
            nn.init.zeros_(self.v_proj.bias)
            nn.init.zeros_(self.out_proj.bias)

        if self.generator_type == "diagonal":
            nn.init.normal_(self.generators, mean=0.0, std=0.02)
        else:
            nn.init.normal_(self.generators, mean=0.0, std=0.02 / math.sqrt(self.head_dim))

        nn.init.normal_(self.theta, mean=0.0, std=0.02)

    def _structured_generators(self) -> torch.Tensor:
        A = self.generators
        if self.generator_type == "full":
            pass
        elif self.generator_type == "symmetric":
            A = 0.5 * (A + A.transpose(-1, -2))
        elif self.generator_type == "skew":
            A = 0.5 * (A - A.transpose(-1, -2))
        else:
            return A

        if self.stabilize_generators:
            d = A.shape[-1]
            eye = torch.eye(d, dtype=A.dtype, device=A.device)
            tr = A.diagonal(dim1=-2, dim2=-1).sum(-1)
            A = A - (tr[..., None, None] / d) * eye
        return A

    def compute_metrics(self) -> torch.Tensor:
        if self.generator_type == "diagonal":
            g = torch.einsum("hm,md->hd", self.theta, self.generators)
            return torch.exp(g)

        A = self._structured_generators()
        G = torch.einsum("hm,mde->hde", self.theta, A)
        M = torch.matrix_exp(G)
        return M

    def _apply_masks_explicit(
        self,
        scores: torch.Tensor,
        attn_mask: Optional[torch.Tensor],
        key_padding_mask: Optional[torch.Tensor],
    ) -> torch.Tensor:
        batch, heads, tgt_len, src_len = scores.shape
        neg_large = -1e4 if scores.dtype in (torch.float16, torch.bfloat16) else torch.finfo(scores.dtype).min

        if self.causal:
            causal_mask = torch.ones(tgt_len, src_len, device=scores.device, dtype=torch.bool).triu(1)
            scores = scores.masked_fill(causal_mask[None, None, :, :], neg_large)

        if attn_mask is not None:
            if attn_mask.dtype == torch.bool:
                while attn_mask.dim() < scores.dim():
                    attn_mask = attn_mask.unsqueeze(0)
                scores = scores.masked_fill(attn_mask, neg_large)
            else:
                while attn_mask.dim() < scores.dim():
                    attn_mask = attn_mask.unsqueeze(0)
                scores = scores + attn_mask

        if key_padding_mask is not None:
            scores = scores.masked_fill(key_padding_mask[:, None, None, :], neg_large)

        return scores

    def forward(
        self,
        x: torch.Tensor,
        attn_mask: Optional[torch.Tensor] = None,
        key_padding_mask: Optional[torch.Tensor] = None,
        need_weights: bool = False,
    ):
        batch, seq_len, _ = x.shape

        q = self.q_proj(x)
        k = self.k_proj(x)
        v = self.v_proj(x)

        M = self.compute_metrics()

        if self.generator_type == "diagonal":
            q_tilde = q[:, None, :, :] * M[None, :, None, :]
        else:
            q_tilde = torch.einsum("btd,hde->bhte", q, M)

        k_expanded = k[:, None, :, :].expand(batch, self.num_heads, seq_len, self.head_dim)
        v_expanded = v[:, None, :, :].expand(batch, self.num_heads, seq_len, self.head_dim)

        if self.use_sdpa and not need_weights and key_padding_mask is None:
            out_heads = F.scaled_dot_product_attention(
                q_tilde,
                k_expanded,
                v_expanded,
                attn_mask=attn_mask,
                dropout_p=self.dropout if self.training else 0.0,
                is_causal=self.causal,
            )
            out_heads = out_heads.transpose(1, 2).contiguous()
            out_heads = out_heads.view(batch, seq_len, self.num_heads * self.head_dim)
            out = self.out_proj(out_heads)
            out = self.resid_dropout(out)
            if self.return_metrics:
                return out, M
            return out

        scores = torch.einsum("bhtd,bhsd->bhts", q_tilde, k_expanded)
        scores = scores / math.sqrt(self.head_dim)
        scores = self._apply_masks_explicit(scores, attn_mask, key_padding_mask)
        attn = torch.softmax(scores, dim=-1)
        attn = self.attn_dropout(attn)
        out_heads = torch.einsum("bhts,bhsd->bhtd", attn, v_expanded)
        out_heads = out_heads.transpose(1, 2).contiguous()
        out_heads = out_heads.view(batch, seq_len, self.num_heads * self.head_dim)
        out = self.out_proj(out_heads)
        out = self.resid_dropout(out)

        if need_weights:
            return out, attn
        if self.return_metrics:
            return out, M
        return out
```

# 23. Research questions to test

## 23.1 Expressivity

Can

$$
M_h = \exp\left(\sum_{r=1}^{m}\theta_{hr}A_r\right)

produce sufficiently diverse attention maps with $m \ll H$?

## 23.2 Redundancy

Do learned $M_h$ matrices lie on a low-dimensional manifold even when $m$ is moderately large?

## 23.4 Structured efficiency

Can diagonal or block-diagonal generators match full generators on small tasks?

## 23.5 KV-cache savings

Can a shared K/V cache with generated metrics preserve quality compared to MHA, MQA, or GQA?

# 28. Main mathematical identity to keep in mind

The entire idea is built around this chain:

$$
M_h = \exp\left(\sum_{r=1}^{m}\theta_{hr}A_r\right),
$$

$$
\mathrm{score}_{ij}^{(h)} = q_i^TM_hk_j,
$$

$$
q_i = W_Qx_i,
\qquad
k_j = W_Kx_j,
$$

therefore

$$
\mathrm{score}_{ij}^{(h)}
= x_i^T W_Q^T M_h W_K x_j,
$$

so

$$
\boxed{B_h = W_Q^T M_h W_K.}
$$

This is the clean relation between the generated latent-space metric $M_h$ and the original-space head geometry $B_h$.
